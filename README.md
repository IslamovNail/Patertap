# PaterTap — Full-stack MVP

Русскоязычный MVP сервиса поиска жилья и соседей для Алматы. Визуальная система развивает предоставленный HTML-прототип; исходник сохранён в `prototype-reference.html`.

## Технологии и решения
- **Flask + Python**: небольшой сервер с REST API, проще запускать локально без отдельного Node toolchain.
- **SQLite**: база для локального MVP; схема и индексы создаются автоматически. Для публичного развёртывания рекомендован PostgreSQL.
- **PBKDF2-HMAC-SHA256**: хеширование паролей (310 000 итераций), случайная соль.
- **Vanilla JS**: без лишнего клиентского фреймворка, адаптивный интерфейс.
- Токен авторизации хранится в `localStorage` для простоты MVP. Для production следует перейти на Secure/HttpOnly/SameSite cookie-сессии и CSRF-защиту.

## Возможности
- Регистрация, вход/выход, проверка возраста от 17 лет.
- Редактирование профиля и бытовых предпочтений.
- CRUD объявлений на API (создание/просмотр/редактирование/удаление; редактирование и удаление проверяют владельца).
- Поиск по ключевому слову, району, бюджету и типу жилья.
- Избранное в БД.
- Каталог соседей с объяснимой взвешенной совместимостью. Процент показывается только при наличии не менее 50% весов с заполненными данными; неизвестные ответы исключаются из знаменателя.
- Приватные диалоги и сообщения, проверка членства в диалоге, ограничение 12 сообщений/минуту на пользователя.
- Блокировка пользователя и подача жалобы.
- Демонстрационные карточки помечены как демо и не являются настоящими объявлениями.
- Защитные HTTP-заголовки, ограничения длины, проверка входных данных и ограничение тела запроса.

## Локальный запуск
Нужен Python 3.10+.

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Сгенерируйте свой PATERTAP_SECRET и загрузите его в окружение; не коммитьте .env.
python app.py
```

Откройте http://127.0.0.1:5000. База `patertap.sqlite3` создаётся автоматически.

### Демо-данные (необязательно)
```bash
python seed.py
```
Учётные записи фиктивные: `demo1@patertap.local` и `demo2@patertap.local`, пароль `DemoPass123!`. Использовать только локально. После теста смените/удалите демо-аккаунты.

## Развёртывание и production checklist
1. Разверните приложение за HTTPS reverse proxy (например, Gunicorn + Nginx или управляемый Python-хостинг).
2. Замените SQLite на PostgreSQL и настройте резервные копии/миграции.
3. Установите `PATERTAP_SECRET` из secret manager; не храните секреты в репозитории.
4. Перенесите изображения в объектное хранилище с проверкой MIME/magic bytes, ограничением размеров и сканированием. Загрузка изображений пока не реализована.
5. Переведите токен в Secure/HttpOnly/SameSite cookie, добавьте CSRF-защиту, ротацию/отзыв сессий и rate limit для входа/регистрации.
6. Настройте подтверждение email и восстановление пароля через почтового провайдера — сейчас нет SMTP-провайдера и поток восстановления не подключён.
7. Для real-time сообщений подключите WebSocket/SSE; сейчас клиент загружает сообщения по запросу.
8. Проверьте применимые требования законодательства Казахстана, согласия/политику приватности и допустимость возрастного порога с юристом. Проверка 17 лет в коде — техническое правило MVP, не юридическое заключение.
9. Добавьте CSP nonce вместо `unsafe-inline`, централизованный аудит событий, мониторинг и административный интерфейс модерации.
10. Настройте production server, логирование, TLS, ограничение попыток входа и автоматические security tests.

## Известные ограничения
- Вход и регистрация реальные для локальной базы, но нет подтверждения email/восстановления пароля.
- Фотографии, карта, real-time чат, административная панель и push-уведомления не реализованы.
- Избранное и сообщения работают через API, но обновляются без real-time.
- Совместимость — эвристическая стартовая модель, а не научный прогноз. Дата заселения пока исключается из оценки, поскольку профиль не хранит дату заселения.
- Фильтры и API реализованы; редактирование/удаление доступны через API, но UI-кнопки управления собственными объявлениями пока не добавлены.
- Тесты покрывают основные API-сценарии, но не заменяют полноценный e2e, нагрузочный и security аудит.
